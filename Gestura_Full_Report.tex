% 2. Abstract
\begin{abstract}
American Sign Language (ASL) serves as a primary means of communication for many Deaf and hard-of-hearing individuals, yet significant barriers persist when interacting with non-signers in educational, medical, and everyday environments. Motivated by first-hand experiences with communication accessibility challenges within my own family, this project introduces \emph{Gestura}, an AI-powered mobile application designed to make ASL translation more intuitive, portable, and inclusive. Existing ASL technologies tend to be fragmented—limited to isolated gestures, reliant on bulky hardware, or dependent on cloud servers that introduce latency and privacy concerns. Gestura addresses these gaps through a unified architecture that integrates real-time ASL recognition, natural-language sentence generation using GPT-3.5, multilingual translation, and animated text-to-ASL avatar output via Hand Talk.

The system combines on-device temporal gesture models with cloud-backed data pipelines for validation, contributor management, and secure model updates. ASL inputs are translated into gloss sequences and then transformed into fluent sentences using large language models, enabling more natural communication than character- or word-level output. A guided capture workflow enables community-driven dataset growth, while a role-gated reviewer mode supports dataset curation and continuous retraining. This paper presents the system architecture, modeling methodology, Firebase data design, and phased implementation plan, and defines evaluation metrics across accuracy, latency, and usability. The long-term vision is to deliver a scalable, privacy-preserving platform that empowers real-time communication and supports future integrations such as wearable smart glasses.
\end{abstract}

% 4. Introduction & Related Work
\section{Introduction}
American Sign Language (ASL) is a rich, fully expressive visual language used by millions of Deaf and hard-of-hearing individuals. However, communication between ASL users and non-signers often depends on human interpreters, written notes, or slow text-based exchanges. My personal motivation for this project comes from growing up in a family where my aunt, who is hard of hearing, relied heavily on ASL. Watching my mother and relatives learn to sign—and witnessing the challenges they faced finding modern, accessible ASL tools—inspired the creation of a more intuitive, mobile-first translation system.

\emph{Gestura} is an Android-based application that performs:
\begin{itemize}
    \item Real-time on-device ASL recognition using temporal models optimized with TensorFlow Lite.
    \item Natural-language sentence generation from ASL gloss using OpenAI's GPT-3.5-Turbo.
    \item Multilingual text and speech translation.
    \item Reverse translation through an animated ASL avatar integrated via the Hand Talk SDK.
\end{itemize}

\subsection{Related Work}
Existing research has explored various facets of ASL recognition. Bantupalli and Xie \cite{bantupalli2018asl} demonstrate how temporal models like RNNs/LSTMs improve accuracy over static classifiers by capturing the dynamic motion of signing. Karthikeyan \cite{karthikeyan2018mlmobile} emphasizes the necessity of on-device inference for real-time mobile applications. Roh et al. \cite{roh2021data} focus on the importance of robust and diverse data collection pipelines.

% 5. Problem Definition
\section{Problem Definition}
Despite progress in ASL research, there is no comprehensive, mobile-first platform that recognizes dynamic, continuous ASL gestures, produces fluent sentences, supports multilingual communication, and incorporates scalable community-driven dataset expansion.

\subsection{Specific Goals and Deliverables}
\begin{itemize}
    \item Develop an Android application capable of real-time ASL recognition.
    \item Implement temporal gesture recognition models for dynamic sign interpretation.
    \item Integrate gloss-to-sentence generation using LLMs.
    \item Support multilingual translation for broader accessibility.
    \item Implement a guided contribution workflow and a Firebase-backed dataset pipeline.
\end{itemize}

\subsection{Specifications and Constraints}
\textbf{Capabilities Enabled:} Real-time inference on-device, cloud-based data management, multilingual support, and text-to-ASL avatar rendering.
\textbf{Constraints:} Mobile hardware limits model complexity; recognition accuracy is sensitive to lighting and background; initial vocabulary is restricted to high-frequency signs.

\subsection{Impact Analysis}
\textbf{Individual:} Improved independence and communication access for Deaf individuals.
\textbf{Organizational:} Enhanced inclusivity in healthcare and education.
\textbf{Societal:} Increased accessibility awareness and promotion of inclusive AI.

\subsection{Issues and Responsibilities}
The project addresses professional responsibility for reliability, ethical considerations in dataset bias, legal compliance with data privacy, and security in handling user-contributed video data.

% 6. Methodology
\section{Methodology}
Gestura follows a hybrid edge–cloud architecture. Inference happens on-device to minimize latency and protect privacy. The cloud is used for heavy-lifting tasks like dataset curation, reviewer auditing, and delivering model updates. A Python-based server handles high-throughput landmark extraction on ports 8000 (batch) and 5001 (live).

% 7. Concepts Considered
\section{Concepts Considered}
Technical decisions included selecting the development environment, backend infrastructure, and processing algorithms.
\begin{itemize}
    \item \textbf{IDE:} Android Studio vs. Visual Studio Code.
    \item \textbf{Backend:} Firebase vs. Custom FastAPI Server.
    \item \textbf{Processing:} MediaPipe Holistic landmarks vs. Raw RGB Video.
    \item \textbf{Networking:} Standard HttpURLConnection vs. OkHttp 4.x.
\end{itemize}

% 8. Concept Selection
\section{Concept Selection}
\begin{itemize}
    \item \textbf{Android Studio} was selected for its native tools and emulator support.
    \item \textbf{Firebase} was chosen for rapid development and built-in authentication/storage scalability.
    \item \textbf{MediaPipe Landmarks} were selected to reduce data dimensionality and improve privacy.
    \item \textbf{OkHttp 4.x} was selected for modern, extension-function-based networking.
\end{itemize}

% 9. Design and Implementation
\section{Design and Implementation}
The app uses a modular fragment-based design:
\begin{itemize}
    \item \textbf{OnDeviceCaptionFragment:} Core translation engine using CameraX and TFLite.
    \item \textbf{ContributeFragment:} Guided capture with validation logic.
    \item \textbf{AvatarFragment:} WebView-based integration of the Hand Talk SDK.
    \item \textbf{DevReviewFragment:} Role-gated triage tool for accepted/rejected gestures.
\end{itemize}

% 10. Conclusion/Summary
\section{Conclusion}
Gestura successfully demonstrates a scalable, privacy-aware ASL translation platform. By utilizing on-device inference and community-driven data pipelines, it bridges the gap between Deaf and hearing communities effectively.
